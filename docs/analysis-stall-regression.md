# 圈选失败与“正在理解”不结束

## 可复现根因

1. `looksLikeEnclosingStroke → looksLikeDrawnLine → looksLikeXStroke → looksLikeEnclosingStroke` 构成循环调用。普通干净椭圆未必进入；收尾略有重叠、自交的扁长圈线会进入并抛出 `Maximum call stack size exceeded`。
2. 几何分类和目标命中在同一 try 中，前者抛错会跳过命中。提交要求又在设置 analyzing 后同步调用几何解释器，没有异常恢复，于是页面停留在等待状态。
3. 旧超时仅 abort 网络 fetch，不能结束正在等待的截图生成；截图本身卡住会无限等待。
4. 扁长圈线还可能通过下划线或箭头的宽高比规则。内部拼接的“补充的信息”也可能被本地关键词推断当成“新增内容”，并非用户真实指令。

## 修复

- 圈选判断仅依赖底层几何度量，不反向调用依赖圈选的分类器。保留圈、叉和线的区分；回描圈不当作删除线或箭头。
- 分类异常不会跳过目标命中；原始笔迹继续作为唯一记录保留。
- 提交异常恢复可编辑状态，保留笔迹及输入，不擅自变成“输入新主标题”。
- 从截图到接口解析共用 14 秒截止时间；过期截图不能再发模型请求；取消或新笔迹使旧任务失效。
- 供模型阅读的对话标签不再参与本地动作关键词匹配。

## 测试证据与边界

新增回描椭圆用例在修复前 3/3 失败，抛出与截图相同的递归栈；修复后通过。

覆盖实际生产几何函数的 48 组比例/起点/开口/回描组合，密集采样箭头回归，实际 overlay 指针事件中的笔迹及区域填充，以及 main.js 控制器中的命中、等待、超时、502、失败后输入恢复。测试注入挂起截图及分类异常，确认按钮恢复可用且不会改动页面。

控制器测试使用 DOM/执行器适配器；不等同于真实浏览器端到端验收。本次未绕过已有浏览器访问拒绝设置，也未声称第三方模型网关的 502 已修复。
