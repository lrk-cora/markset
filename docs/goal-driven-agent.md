# Markset 目标驱动规划改造

日期：2026-10-06。承接百炼迁移，不改变 Codex 对话模型。

## 新链路

1. **观察**：相关区域截图、局部放大图、完整笔迹的均匀采样、精确字符范围、模块树、计算样式、附近空白和箭头端点。统一网页文档 CSS 坐标，保留 viewport 坐标作为单独证据。
2. **理解与设计**：用户原话和保留约束优先。圈选是范围证据，不是替换命令。视觉与复杂任务继续用 Qwen3.8-Max；不每次串联 Flash、Max。
3. **必要时查证**：原生只读工具 `inspect_module`、`inspect_node`、`inspect_relations`，只读取当前相关模块，最多两轮、四次读取。不允许任意选择器、脚本或网络工具。
4. **提交方案**：原生 `propose_edit` 使用结构化参数提交具体设计，不执行网页修改。支持样式、移动、重排、字符删改、新增节点、图片生成/编辑及组合事务。结构化约束用于可执行性，而非把用户目标限制在几个菜单按钮里。
5. **内部验证**：隔离 iframe 副本使用正式执行器，检查内容保留、影响范围、无效布局属性、新增溢出/裁剪/同级遮挡以及撤销恢复。生图规划先使用占位图，不偷偷触发付费生成。
6. **一次修复**：失败反馈具体问题及原方案，最多修复一次；服务端格式/范围修复与客户端执行修复共享这个额度。修复不得偷偷增加写目标或引入未获授权的破坏性操作；原笔迹已经明确划除时，可修正为原目标的删除。无法修复明确提示，不静默降级成“替换文字”。
7. **用户决定**：展示一句具体结果说明和可选补充输入。选择具体候选只更新选择状态；点击“修改”直接执行该方案，不重新把它解释成通用主题。正式页面仅在确认后修改，整组一次撤销。

模型调用使用原生工具参数，不同时叠加 JSON 响应模式；被拒绝的原生提交也返回对应 tool 结果后再修复，避免下一轮协议不完整。网页内容和工具结果是数据，不是新指令。

## 本轮发现的实际问题

| 问题 | 修复 |
| --- | --- |
| 长圈/箭头只发送前 180 个点，模型看到残缺形状 | 均匀采样完整笔迹，保留两端和全形状，原始墨迹不变 |
| 模型选了模块里的合法插入锚点，前端却只检查原选区 | 统一使用选中对象与已观察相关节点校验；读权限不等于任意写权限 |
| 已设计完整新增节点，仍提示“缺内容” | 节点树计为可执行内容，不重复追问 |
| 用户确认具体候选后，又因 UI 标签简化而进入关键词推断 | 按规范化标签匹配真实候选，确认直接执行对应计划 |
| 已提交的回答仍留在草稿里，点击修改再次分析 | 清理已消费回答，保留尚未提交的输入与失败草稿 |
| 整组已告知范围，子步骤仍被重复拒绝 | 组合方案范围声明传递到子步骤，未知目标仍拒绝 |
| `flex-direction` 写在 block 卡片上，合法却没有效果 | 观察真实布局父容器；检查最终计算样式，反馈 `inactive-layout-style` |
| 内部试执行改变正式历史/画布高度，或后台帧等待挂住 | 临时执行上下文同步恢复，禁止试执行缩放掩盖溢出，帧等待可取消且有超时 |

## 可靠性与记录

- 初次分析、只读步骤和修复共享临时失败重试预算，最多重试两次；鉴权、参数等错误不重试。
- 保留全流程超时、取消、过期 revision 拒收、错误提示，以及失败后的笔迹与输入。
- 图像接口原有安全重试、任务 ID 查询、防重复提交与真正原图编辑保留。实际图片准备完成后再次检查，再提交整组 DOM。
- 相关节点写入必须声明额外范围并在简短说明中告知；修复不能扩大原方案范围。
- 右侧 Agent 记录展示观察、结果摘要、校验/修复、来源、耗时和执行结果，不展示内部思维过程，不作为额外历史对话发送给模型。

## 仍需持续评估的边界

- 小样本不是总体准确率承诺。复杂主动查证曾有一次全链 60 秒超时；协议和 schema 优化后的成功例约 30 秒，延迟仍有波动，不宣称超时已绝迹。
- 当前验证是可执行性、影响范围与部分布局质量检查，不是通用审美评审或任意目标的完备语义证明。
- 隔离副本去掉外部图片与外部样式资源，使用尺寸占位；依赖远程字体/样式的页面不能视为像素级复刻验证。
- 圈选但未指定最终效果时可能仍需真正有差异的选择题；不能为了减少提问擅自替换或删除用户内容。

官方协议参考：[Function Calling](https://help.aliyun.com/zh/model-studio/qwen-function-calling)、[结构化输出](https://help.aliyun.com/zh/model-studio/qwen-structured-output)。地域、图像任务协议和先前的付费图像测试见 [百炼迁移记录](bailian-migration.md)。

## 同一菜单反复出现的后续排查

运行中的 5173 服务已提供新 Agent 代码，问题并不是后端仍运行旧模型。根据用户截图进一步发现：

- 停笔后的本地临时菜单立即显示为“请确认范围”，但真实模型仍在请求中；用户无法分辨是否完成分析。现在请求阶段显示 **AI 正在分析**，不把临时菜单当成模型结果；仍允许输入补充要求或继续画。
- 区域几何用轴向宽高及象限判断，部分斜直线也满足“圈选”条件。现使用端点距离、路径长度与垂直偏差排除任意方向的直线；不会把直线填成三角选区。
- 目标按 ID 去重时丢掉了后续笔画的文字命中。现以不改动旧快照的方式合并字符范围，保留最新几何与上下文。
- 曾将任何字符命中硬性限制为“只能删字符范围”，即使视觉判断是整段划除；修复也可能被误判为新引入删除。现保留明确删除证据、合法目标、确认与撤销检查，但允许规划器分辨局部划词与整对象划除。单独圈选仍不能授权删除。
- 原生方案修复失败时，前端诊断现在保留初始方案及校验摘要，避免只看到最后一次报错。
- 等待模型时新输入的、尚未提交的草稿不会因结果返回而被清空。
