# 明确指令重复确认：修复记录

## 原因

- 输入框 Enter 调用 `interpretCustomIntent()`，默认不执行；按钮调用 `interpretCustomIntent(true)`。同样的“提交”实际走了两种流程。
- 完整颜色指令仍调用视觉模型，成功识别后也可能退回本地建议，徒增等待和追问。
- 补充指令的异步结束只检查 group ID，未检查笔迹 revision / 请求是否已作废。

## 调整

- 回车和两个修改按钮共用主动作入口；输入法候选确认、长按回车及禁用态不提交。
- 完整、单动作、作用范围明确且受现有调色板支持的文字改色命令本地生成计划，复用原执行校验、事务记录及撤销链路，不再请求模型。
- 未知颜色、否定、多动作、背景色、部分字词范围等不走该快速路径。模型仍负责复杂理解。
- 用户主动设置先预览时，按按钮显示的动作执行；补充要求不会被旧预览忽略。
- 每次提交取消待执行的笔迹分析；旧请求和旧 revision 均不能触发后续自动执行。
- 显式动作清理旧追问状态；“改成红色”不会因上一轮正在索取新标题而变成替换文案。

## 验证

- `npm test`：81 项通过，含 16 项新增回归。
- `npm run build`：通过；保留原有混合静态/动态导入提示。
- `tests/main-submission.test.js` 加载实际 main.js，触发真实事件绑定和状态渲染，验证提交一次只调用一次改色执行器、关闭建议框、不调用模型，并覆盖输入法、旧问题与预览偏好。
- 此集成测试使用 DOM / 执行器适配器，不是浏览器端到端测试。本轮未绕过先前已保存的 localhost 浏览器拒绝权限，真实浏览器效果仍待复核。
