## 变更

- `routeAnalysis` 固定走已配置的 Flash（默认 `qwen3.8-flash`），包括截图、插图规划、复杂组合笔迹。取消“带截图就 Max”的规则，失败不自动升级或串联 Max。
- `/api/health` 的 `analysisRouting` 公布实际路由策略；记录依然使用实际返回的模型、尝试时序与失败原因。
- 新请求不再要求 `candidatePlans`。确实缺少目标信息时，只给结合页面内容的短澄清选项；用户选定后生成对应方案。旧候选记录和历史执行仍能读取。
- 结构化输出必填字段从 10 项缩为 5 项：操作、结果摘要、短依据、执行策略、目标。执行参数、原图编辑描述、组合步骤、精确范围和扩展范围等仍按操作填写并校验；不靠截断结果来提速。
- 完整方案返回并完成必要检查后一次展示。取消公共草案事件、逐段 JSON 摘要提取和相应 UI 重绘；旧客户端草案也不会冒充完成结果。
- 保留上游内部流式接收，只用于拼接完整输出、取消、首次有效输出/停滞检测与诊断。它不是多次模型调用，切换为非流式不会自动减少生成量，还会失去输出监测能力。
- 记录增加“完整方案返回”耗时。旧记录的首次草案耗时仍如实展示，仅供查看、不发送为模型历史。
- 保留必要的只读查证工具，不强行跳过缺失证据；明确且证据充分的要求通常一次提交。没有自动修复、自动评审模型或多模型串联。
- 连接临时失败仍最多重试两次，60 秒硬总上限不增加；格式、参数、权限错误不重试。确认、撤销、图片任务 ID 和安全重试策略不变。
