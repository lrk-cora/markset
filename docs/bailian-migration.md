## 分流：根据实测而不是置信度

| 情况 | 当前使用 | 理由 |
| --- | --- | --- |
| 完整明确的局部颜色、删除、精确文字替换 | 本地确定性执行，用户点击修改后应用 | 不必等待模型；仍可撤销 |
| 简单纯文本规划 | qwen3.8-flash | 成本与延迟优先，后续继续评估 |
| 含网页截图或笔迹的视觉规划 | qwen3.8-max | Flash 在本次视觉案例中多次返回无效方案，包括严格结构化模式下的 `[]` |
| 多步骤、跨模块、组合笔迹、图片内容规划 | qwen3.8-max | 按可观察复杂度分流，不采用模型自报置信度决定档位 |
| 普通配图、已有图片局部编辑 | qwen-image-3.0 | 真正传入原图再编辑 |
| 精确文字、复杂版面、用户指定高质量 | qwen-image-3.0-pro | 只调用这一档，不重复生成标准版 |

没有常规 Flash → Max 串联。为了效果，目前视觉任务采用更保守、较贵的 Max；不是宣称 Flash 已全面达标。

补充纯文本实测：对已有标题输入“改得更简短，保留科研二字”，没有截图或笔迹，实际分流到 Flash；6.35 秒返回“科研入门”，通过执行校验，既缩短标题又满足保留要求。单例不能替代持续质量评估。

## 请求与执行链路

1. 原始笔迹独立保留，命中只产生对象和范围证据。
2. 收集整页带笔迹缩略图、局部放大图、对象 ID/层级、字符范围、用户指令和获准使用的偏好。
3. 几何证据统一为 **网页文档 CSS 坐标**，保留 viewport 坐标单独标注；缩略图像素不能直接当作 DOM 坐标。
4. 单次分流，请求官方兼容 Chat 接口；禁用额外思考输出。现使用原生只读查证工具与 schema 约束的 `propose_edit`，不同时叠加 JSON 响应模式。只接收可展示结果与可执行方案，不展示内部思维过程。完整后续改造与实测见 [目标驱动 Agent](goal-driven-agent.md)。
5. 验证合法目标、字符唯一匹配、插入锚点、影响范围、步骤依赖和执行能力。校验失败明确显示原因，不静默改成文字替换。
6. 用户点击修改后执行；生图步骤先准备图片，再提交 DOM。多步骤合并成一项事务，失败回滚，一次撤销/重做整个修改。

已修复的限制：

- 圈选命中字符范围不再被当成删除证据；批量方案也不能绕过这一保护。
- 命中文字不等于文字替换，不以本地固定动作覆盖合理的模型方案。
- 选中模块或标题可以作为内部、前后、附近插入的锚点，不要求先清空选区。
- 支持一组多步骤操作、明确重排顺序、图片生成/编辑提示词，不要求用户提供图片 URL 替代生图。
- 英文 CSS 基本颜色名正确转成颜色值；重排撤销精确恢复原本不存在的 style 属性。
- 所选图片有失效目标时整组拒绝，不默默只改剩余一部分。

### 图像协议

使用官方 DashScope **异步图像任务**，不是把模型名塞进旧网关请求：

- 提交 `/api/v1/services/aigc/image-generation/generation`，请求头 `X-DashScope-Async: enable`。
- 文生图只传文本；原图编辑依次传 `{image: 原图}` 和 `{text: 编辑要求}`。
- 获得 `task_id` 后查询 `/api/v1/tasks/{task_id}`，处理等待、运行、成功、失败和未知状态。
- 验证并下载结果，再写入真实 `<img>`，不是整页截图替换。
- 3.0 接口不是硬蒙版 inpaint API。旧 `/api/inpaint` 可作原图+文字编辑；如果传入硬蒙版，明确拒绝，**不忽略蒙版伪装成支持**。

## 可靠性和可观察性

- 分析临时网络错误、502/503/504 最多自动重试两次；鉴权、参数和额度错误不自动重试。单次 30 秒，全链 60 秒，客户端留出截图与传输时间。
- 图片全链 180 秒；安全重试预算一次。只在确认尚未提交的连接失败时重试 POST；收到任务 ID 后只查询该任务。
- 未知提交状态、不明 5xx、无任务 ID 的模糊结果不盲目重新提交，也不自动换供应商。
- 过了 24 小时查询窗口，保留操作身份作为防重记录；重启后也不把过期重试变成新的付费生成。账本仅存小型元数据、容量上限 4096，达到上限拒绝新提交而不是偷偷遗忘未确认任务。
- 客户端合并并发请求，服务端按操作 ID/参数指纹去重。私有任务账本保存任务 ID、地域、模型和指纹，**不保存 Key、原图、提示词或签名结果 URL**；重启仍可查原任务。
- 分析失败保留笔迹与输入，显示错误码、重试操作和本地方案来源。Agent 摘要记录实际模型、分流原因、重试次数、耗时及最终执行结果。
- 快速状态检测仅检查官方模型列表，区分已配置、接口可连接、最近实际调用成功；不会产生图片。实际生图/分析验证有独立计费按钮和明确确认。
- 实际图片验证超时后沿用同一操作 ID，查询原任务，不另开付费任务。
- Agent 记录为本次会话内的展示数据，可以清空；不追加为模型历史对话。用户行为偏好仍是独立、可管理的授权记忆。

## 实测（真实官方调用，不是 mock 返回）

测试页含标题、局部文字、两张卡片、模块和杯子图片。截图来自真实浏览器渲染；模拟圈选、划线、箭头和文本要求。下列是小样本观测，**不是长期准确率或可用性承诺**。

### 两档对照：7 个场景 × 2 轮 × 2 个模型 = 28 次

| 指标 | Flash | Max |
| --- | --- | --- |
| 返回可解析、目标动作符合预期的方案 | 9/14 | 14/14 |
| 无效方案返回 | 5/14 | 0/14 |
| 最初通过应用执行校验 | 9/14 | 13/14 |
| 平均响应耗时（包括快速失败） | 4.71 秒 | 9.63 秒 |

Max 的一个多步骤计划只因缺少步骤说明被拒绝；已改为按既定操作补足说明，不改动作本身。Flash 的问题不能简单归因于本地过滤：实际捕获过原始结果为空数组。复杂图像插入、编辑和批量操作是尤其需要 Max 的案例。

### 最终分流与结构化协议回归

| 案例 | 结果 | 分析耗时 |
| --- | --- | --- |
| 仅圈住标题，没有明确动作 | 识别范围并给澄清；没有擅自删除或替换 | 9.10 秒 |
| 划过“冗余说明” | 精确删除该四字范围，保留其余文字 | 9.15 秒 |
| 将右侧卡片移至左侧 | 明确重排顺序，保持文案 | 10.93 秒 |
| 标题改红 | 颜色方案，不把指令当作新文字 | 7.58 秒 |
| 模块内增加科研配图 | 内部插入图片，保留标题和说明 | 12.91 秒 |
| 杯子变蓝，保留其他细节 | 原图编辑方案，不是从零生图 | 9.36 秒 |
| 卡片纵排，同时标题变红 | 两步事务方案 | 18.02 秒 |

7/7 符合预期；其中 6 项可执行计划全部通过生产 DOM 执行器的内容质量、单项历史、精确撤销/重做检查。圈选澄清没有改变 DOM。这一轮没有网络/解析失败。
