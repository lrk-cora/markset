# 单次方案：关闭自动修复

日期：2026-10-07，按用户最新要求替代之前的自动局部修复策略。

## 原因与修改

原来后端对无效 JSON、目标引用等校验失败会再次规划；前端对隔离执行或最终图片定位校验失败也会发出 `repairFeedback`。两条路径共享两次修复额度，增加等待与费用。

现在 `planRepairs=0`，两条自动调用路径均已移除，不只是隐藏“修正中”文字。

- 已生成的方案不再因内容、审美、重复澄清或缺少理想效果而重新生成。
- JSON/工具结构、合法目标、字符范围、锚点、脚本隔离、范围外内容保护和撤销能力仍检查；失败直接停止并提示，格式错误也不调用模型自动修正。
- 无效布局属性、内容与设计建议只是提醒；轻微溢出按既有策略放行。实际遮挡、严重溢出、错误图片位置或范围外删改仍安全停止，不能把执行损坏当作内容问题放行。
- 圈选本身不是删除命令；本地兜底不能据此自动删除。模型可基于完整视觉证据给出删除建议，合法目标/字符范围的建议需用户确认，不再受本地“未认出划除”规则否决。
- 前端检查失败保留首次方案；后端无效提交保留可解析的结果摘要。保留笔迹、输入和已生成图片，不转成固定菜单，不自动应用。
- 新记录修复次数为零，旧记录仍可如实显示历史次数。只读查证属于首次方案的证据准备，不属于重新设计。
- 仅用户显式点击重试/提交新要求才重新分析；已生成图片按相同任务身份与资源缓存复用，不自动重复生图。
- 临时连接失败仍最多重试两次；生图安全重试一次、任务查询与去重规则不变。旧客户端的自动修复请求在任何付费模型调用之前拒绝。

## 验证

- 自动回归 414/414，通过真实 HTTP 中间件、流式输出、控制器和 DOM 执行器的故障注入。
- 无效 JSON/插入锚点仅一次模型调用；旧 `repairFeedback` 请求零次模型调用。
- 前端试执行和应用阶段失败不重新分析，原方案/输入/笔迹保留；内容提醒可确认执行。
- 图片定位失败保留资源，用户主动重新分析并确认后复用图片，无重复生成。
- 连接失败恢复、总超时、侧栏重排、合法范围、单项撤销等旧保护仍通过。
- 构建通过；运行中的 `/api/health` 已返回 `planRepairs: 0`。上述测试使用受控模型/图片响应，不产生付费生成，不能据此声称真实模型准确率提升。
- 独立 Chrome 的真实圈选/UI 回归：无效布局效果仅提醒，首次方案可确认应用且一次撤销精确恢复；插入锚点失效时保留原建议和墨迹、停止应用。两个案例各只有一次分析请求，没有自动修复。分析与生图接口均拦截，未产生付费调用；独立浏览器已关闭。
