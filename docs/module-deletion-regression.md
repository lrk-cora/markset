# 明确删除却依赖网关、只删除部分字词

## 根因与修改

- 完整颜色指令有本地快速执行通道，但删除没有：即使“去掉这块内容”已给出动作和当前选区，提交仍先调用视觉分析接口。
- 本地删除计划继承几何解释器的字符 `targetRanges`，导致“移除整个对象”误走局部文字删除执行器。
- 旧的替换内容澄清分支可能把新的删除/改色/范围纠正指令当成替换文案。
- 父组件与子节点同时选中时，旧执行器分别快照、依次删除，再过滤空占位符，可能使删除记录索引错位；中途失败也没有整组回滚。
- 原撤销占位符是有高度的零宽度 inline-block，仍会参与网格、弹性布局。

现在统一解析可确定的当前指令（颜色、整对象/局部文字删除、精确文字替换），新指令覆盖旧建议，不必等待模型。整对象删除从干净状态创建计划；局部删除则保留并验证明确的字符范围。否定、限定对象不明、复合请求不能降级为“删除全部”。

实际删除只处理最外层选中节点，整组成功才登记一次历史，中途失败回滚。撤销锚点 `display:none!important` 不占布局位置，撤销/重做保留原有 DOM 层级。

## 验证与边界

- `tests/deletion-intent.test.js`：完整/限制/否定/局部/过期范围指令。
- `tests/main-submission.test.js`：真实提交处理器，旧替换问题和选项覆盖，502 降级不误删，显式预览偏好。
- `tests/web-doc-deletion.test.js`：JSDOM 中调用生产网页执行器，实际移除组件、局部删词、保留邻居、父子去重、撤销/重做、注入失败回滚。

这些是自动化逻辑/DOM 集成测试，不是实际浏览器布局验收。未访问用户浏览器，也未关闭 iframe 脚本隔离。

`/api/brush-intent` 的 502 是服务端调用网关失败的响应；截图不足以区分网络、超时、上游错误或空响应。本次让明确删除不再依赖该请求，并不表示已修复第三方网关。

修改范围仍以当前高亮的页面对象为准。只高亮标题时，不会擅自向上删除整个未选中的首屏/父模块；明确删除也不能操作未标记对象或网页根节点。
