# Markset 人机交互论文研究方案

**建议主线：研究非前端用户如何用原位笔迹与简短文字，在已有网页上表达局部修改意图，并保持对作用范围和结果的控制。** Markset 是研究原型，不应包装成“首次把画笔接入大模型”或“已经证明更高效”的系统。

研究对象暂定为需要调整网页内容的内容创作者、运营编辑或设计人员；参与者应有真实编辑需求，但不以熟悉 HTML/CSS 为前提。当前系统处理导入的 HTML 快照，不等同于直接改写任意在线网站的服务器代码。

[文献地图与差异定位](./literature-map.md)包含关键近邻、正式来源及需要避免的原创性主张。

## 论文定位

中文暂题：**Markset 通过原位笔迹与自然语言表达网页修改意图及作用范围**

英文暂题：*Markset: Communicating Scope and Intent for Web Editing through In-Situ Marks and Natural Language*

问题不是“模型能否猜出一个圈是什么”，而是用户如何表达四件事：**哪里是修改对象、希望得到什么效果、哪些内容必须保留、何时授权实际修改**。相同圈选可能用于改色、精简、删除或添加旁边的图片；仅知道命中文字不能确定动作。真正有多种取舍时允许澄清，避免把所有圈选默认变成替换。

已有 [Code Shaping](https://www.wvisdomlab.com/papers/code-shaping.pdf)、[SketchGPT](https://orca.cardiff.ac.uk/id/eprint/181362/)和 [AnnotateGPT](https://vialab.github.io/AnnotateGPT/)已经研究 AI 对笔迹的理解及用户确认。因此，Markset 的价值需要通过网页编辑领域的具体机制与实证发现建立，而不能仅靠更换模型或组合已有功能。

## 拟形成的贡献

1. **网页修改意图的实证描述**：描述用户如何用点、线、圈、框、箭头和短文字表达对象、动作、关系及保留约束，识别字符、对象、模块和空白位置之间的范围歧义。需要形成性研究支持，不把当前项目截图当作正式用户数据。

2. **范围与目标分离的交互设计**：结合笔迹、页面截图与 DOM 证据，形成具体局部方案；通过共享区域编号、结果摘要、明确确认和整组撤销，使用户能检查实际意图。系统原型支撑这一设计，但其额外价值仍需对照实验。

3. **受控比较及可复现的任务材料**：在相同模型与执行后端下，比较纯文字、常规选择加文字、原位笔迹加文字，报告成功、耗时、指代负担、越界修改与用户控制感；在许可范围内公开脱敏任务、评分标准和分析方法。

不作为核心贡献：Flash 比 Max 快、区域序号、画笔粗细设置、接口重试、状态图标或大量单元测试。它们是实现与可靠性条件。个人符号学习目前没有跨用户或长期效果证据，先放入局限与后续工作。

## 当前原型与证据边界

| 能力 | 当前状态及论文表述 |
| --- | --- |
| 标记与观察 | 支持单点及自由笔迹、多区域编号、文字范围、截图、模块结构和空间关系。已有实现；需系统评估不同笔迹与布局。 |
| 修改规划 | 结构化方案可组合样式、字符修改、删除、插入、移动及图片操作，必要时只读查证。不是固定几个按钮的分类器。 |
| 应用与撤销 | 隔离副本检查部分执行、范围及布局约束；用户确认后应用；组合修改可一次撤销。不是任意页面的完备语义或审美证明。 |
| 图片流程 | 从零生成与已有图片编辑分开；编辑传入原图；生成资源还需按锚点插入网页。规划正确、生图成功、插入正确分别评估。 |
| 模型与延迟 | 最新实现固定使用 qwen3.8-flash；完整方案一次展示；必要只读查证保留。不能描述成当前自动 Flash/Max 分流或逐步草案。 |
| 失败与修复 | 自动方案修复已关闭；临时传输失败仍有有界重试。安全或格式失败停止并保留笔迹、输入与资源，是否重新分析由用户决定。 |
| Agent 记录 | 会话内显示摘要、来源、耗时及结果；不展示内部思维、不作为额外模型对话。当前最多 100 条且刷新不保留，不是完整研究数据记录器。 |

当前版本以 [Flash 快速规划记录](https://github.com/lrk-cora/markset/blob/7c58efd3ab2b0b8254d867fc1af24bd6e3225f4e/docs/flash-fast-planning.md)、[单次方案策略](https://github.com/lrk-cora/markset/blob/7c58efd3ab2b0b8254d867fc1af24bd6e3225f4e/docs/single-proposal-policy.md)及相应实现为准，早期文档中 Max 路由与自动修复过程属于历史版本。

已有工程记录包含 416 项回归通过，以及真实页面标题圈选约 9.29 秒、模块补图规划约 12.84 秒的个例。补图个例使用占位图检验位置与撤销，未实际生图。这些记录支持原型可运行，**不构成总体准确率、用户效率提升或图片效果稳定性的统计证据**。

## 研究问题

- **RQ1 表达方式**：用户会怎样标记网页修改？哪些标记负责指代，哪些表达动作或空间关系？什么时候需要补文字或澄清？

- **RQ2 额外价值**：在相同 AI 与执行条件下，原位笔迹相对于纯文字和常规选择，是否降低指代负担，并改善任务成功和完成效率？

- **RQ3 控制与错误恢复**：用户能否理解方案会影响哪里，发现越界或错误位置，并通过拒绝、补充要求或撤销恢复？这些行为与等待时间有什么关系？

预注册可检验预期：笔迹可能在跨区域关系与空白插入任务中更有优势，在单对象改色中优势较小；表达成本下降不一定抵消模型等待；短结果说明与可逆操作可能提高控制感，但也可能导致用户过度依赖摘要。它们是待检验预期，不是结论。

## 形成性研究

建议先招募 **8 至 12 名**有网页编辑需求的非前端用户；这是质性研究的起始规模，不是统计功效保证。根据观察的覆盖与招募条件调整，并报告停止招募的依据。

让参与者在现有网页截图或早期原型上表达修改，不先教“圈等于某个命令”。提供目标明确的任务，也安排一个目标开放的设计任务。访谈他们为什么这样画、哪些内容必须保留，以及误解后会怎样补充。

分析单个标记的角色及多个标记的组合；特别记录圈标题但在旁边补图、箭头两端指代、划掉部分文字、模块内新增和不同大小选区。建立代码本，两位研究者独立编码一部分材料并讨论分歧，公开分析过程。探索性访谈可采用出声思考，正式计时比较尽量使用事后回顾，避免思考过程改变速度。

产出应是任务分类与设计需求，不只是“参与者喜欢画笔”。当前项目迭代可提供动机和故障案例，但不能替代这一步。

## 技术评测与任务库

建议建立 **12 个不同布局页面，每页 6 类明确目标，共 72 个任务实例**。页面同时覆盖学习资料、活动说明、产品介绍与信息卡片等结构；开发与调参用页面和正式评测用页面按模板划分，避免同模板泄漏。

| 任务类型 | 示例目标 | 必须检查 |
| --- | --- | --- |
| 圈选与精确改色 | 指定标题变为目标色，正文不变 | 目标命中、颜色、文本保留 |
| 划除删除 | 删除一段冗余短语，保留同句其余部分 | 字符范围、非目标文字 |
| 移动或重排 | 将指定卡片移至另一卡片前 | 相对顺序、内容与关系保留 |
| 模块内补图 | 在说明下方、按钮上方补相关图 | 合法锚点、原文、位置、布局 |
| 已有图片编辑 | 改背景或局部细节，保留主要对象 | 确实传入原图、保留约束、回填 |
| 跨区域组合 | 标题改色，并在右侧空白补图 | 多区域对应、组合效果、整组撤销 |

每例建议重复 3 次观察随机波动，即每配置 216 次分析；比较多配置会增加调用量，实施前单独确认预算，本轮没有执行这些付费实验。轮次按时间块交错，记录缓存命中及服务时段。

分别报告目标定位、最终效果、格式合法率、执行成功率、严重越界率、超时率及中位数和 P90 延迟。圈选但未提供最终效果的材料单列为歧义任务：询问合理澄清可以是正确行为，不能凭研究者猜测给它任意动作标签。

主比较先固定图片素材，把图片位置与布局质量和生成质量拆开；真实生图及编辑另做端到端子评测。原图编辑除协议证据外，还需盲评对象与细节是否保留。占位图通过不算真实图片任务完成。

## 主用户研究的公平基线

建议被试内比较三个条件。正式参与者计划 **24 至 30 名**，最终人数根据先导任务方差、最小有意义差异及功效或精度分析确定，不以惯例人数保证显著。

| 条件 | 可用输入 | 主要检验 |
| --- | --- | --- |
| A 纯文字 | 看同一网页，用文字描述对象、位置和效果 | 常规文字指代的成本 |
| B 常规选择加文字 | 点选、字符选择或矩形框选；支持多个区域 | 视觉定位本身能解释多少收益 |
| C Markset | 原位点、线、圈、框、箭头等笔迹，加可选文字 | 笔迹语义和空间关系的额外价值 |

三组共享模型版本、截图质量、DOM 上下文获取预算、执行器、检查、超时、重试、图片素材、确认和撤销。B 同样显示区域编号；不故意限制成单区域，也不要求 A/B 写 CSS、手动复制代码或使用较弱模型。

采用平衡的条件顺序和匹配的不同页面任务集，避免重复完成同一题造成记忆收益。建议每条件 4 个任务，共 12 个计时任务；六类任务在参与者间平衡分配。用先导测试确定单任务上限及总时长，目标约 60 至 90 分钟，不能把训练和问卷时间漏掉。

加入一次自由编辑及事后访谈，了解用户何时偏向文字、选择或笔迹。主实验固定鼠标或笔设备；若两类设备都测，须单独平衡并分析，不能把设备优势混作画笔机制优势。三种研究界面仍需实现，本轮未修改应用。

## 指标与分析

**主要结果是任务成功及成功所需的完整代价，而不是模型自评正确。**

- 任务成功：完成目标且满足保留、位置及严重布局约束。规则先写清；明确区分正确方案、实际应用及最终完成。

- 时间：从读完任务开始操作到完成确认，包含绘制、输入、澄清、AI 等待、检查、应用、用户主动重试及撤销。另记录主动表达时间和系统等待，解释提速是否真的转化为整体收益。

- 指代负担：用户为说清对象及位置而输入的内容、表达时间、澄清轮数、重画或重选次数。总字符数只是辅助指标，不能忽略画笔投入或用户复制任务说明的影响。

- 范围错误：错误对象、字符范围过大或过小、错误插入位置及不期望的非目标内容变化。预期的响应式重排或必要父容器调整不自动算越界，需依据预先规定的允许影响范围判断。

- 用户体验：按固定版本使用 [NASA TLX](https://www.nasa.gov/human-systems-integration-division/nasa-task-load-index-tlx/)；另以明确标为自编的题目询问理解方案、控制感、等待可接受性及恢复能力。

- 修改质量：两位不知道条件的评分者按内容保留、目标符合、可读性及布局评分；分开报告客观规则和审美判断，给出评分一致性与分歧处理。

所有失败、取消和超时保留在分母里。不只统计成功任务耗时后宣称更快；可并列报告固定时限成功率、截至时限的受限任务耗时和成功条件下耗时，后一项明确为次要结果。

分析考虑参与者与任务的重复测量，使用适当的混合效应或配对分析，报告效应量与置信区间。预先指定 A/C 与 B/C 的比较和主要指标，处理多重比较；模型的三次重复不是三个独立用户。正式研究不修改提示词或挑选好看的成功例替换失败。

## 研究前需要补的最小工程

1. 三个公平的输入条件，以及同一后端配置冻结方式。

2. 经同意开启的研究事件记录与导出；当前右侧会话日志会刷新丢失，不能直接充当实验数据。

3. 页面与任务版本、目标和保留约束的评分定义；字符、节点、位置及图像编辑的验收工具。

4. 覆盖真实图片回填、响应式重排和整组撤销的端到端回归。

5. 可区分表达、推断、格式、执行、布局与服务失败的事件编码。

建议记录匿名参与者编号、条件、任务、时间戳、目标引用、笔迹点列、明确输入、方案摘要、确认拒绝、模型请求与读工具次数、阶段耗时、失败类型和 DOM 差异。冻结代码提交、提示词哈希、模型实际返回名称、地域、设备、视口及重试策略。不要采集 API Key、登录状态或模型内部思维；研究日志不追加到模型历史。

只在同意与用途允许时保存截图和原始输入。默认使用研究用公开或合成网页，原始身份信息与研究数据分开存储。研究代码与真实用户数据不自动上传 GitHub。

## 论文结构与图表

1. **Introduction**：已有网页局部修改的指代与保留问题，研究问题及拟贡献。

2. **Related Work**：直接操作、笔迹理解、可控局部修改、视觉定位四条线，与近邻正面比较。

3. **Formative Study**：任务、用户自然标记、歧义及得到的设计需求。

4. **Markset Design**：范围与目标分离、共享指代、结果说明、确认及可逆性。

5. **Implementation**：截图与结构证据、受控工具、隔离检查、图片执行及故障处理；模型名称只是配置。

6. **Technical Evaluation**：独立任务集、错误分解、延迟与图片子评测。

7. **User Study**：公平基线、任务分配、真实过程、指标及结果。

8. **Discussion and Limitations**：哪些任务适合画、何时文字更好；等待、误解与用户控制的取舍；模型和页面覆盖边界。

9. **Conclusion**：只概括数据真正支持的发现。

## 摘要草案

已有网页的局部修改要求用户同时表达修改对象、期望效果及需要保留的内容。我们研究原位笔迹与自然语言如何支持非前端用户传达这些意图，并实现 Markset 研究原型。系统结合视觉标记、文字范围和页面结构生成局部修改方案，通过简短结果说明、明确确认及可逆事务保留用户决定权。研究将分析用户自然标记方式，并在相同模型与执行条件下比较纯文字、常规选择加文字和原位笔迹加文字，评估任务完成、指代负担、非目标内容变化及控制感。目标是识别笔迹交互的适用任务、歧义和等待成本，为可控的 AI 网页编辑提供实证依据。

这是研究方案摘要，尚不包含实验发现；正式论文必须用完成的研究方法与真实结果替换将来时表述。

## 推进顺序与发表边界

先确定用户与任务，再做形成性研究；随后冻结原型、补公平基线和记录导出，完成技术任务库及小规模先导，最后开展主实验和论文写作。不要先扩展更多功能，再寻找一个能证明全部功能有效的实验。

当前原型适合开始研究与演示准备；单凭工程回归和几次模型调用，还不足以宣称强 HCI 实证贡献。若后续发现优势仅集中在跨区域任务，论文应收敛到这一发现；即使整体速度没有提高，范围误解与纠正行为的扎实研究仍可有价值，但不能写成效率提升。

招募和记录真实参与者前，按机构要求完成伦理审查或相应审查安排，准备知情同意、退出、补偿和数据处理说明；相关要求可参考 [ACM CHI 的作者政策](https://chi2026.acm.org/authors/papers/)，实际投稿以目标届次规则为准。说明模型服务会处理哪些截图与文本，并保留 AI 辅助研究和写作的使用记录。

研究成熟后，若重点是行为与设计发现，可按 CHI 方向完善；若形成有明显新机制的交互技术，可考虑 UIST；若重点是智能交互及评估，可参考 [IUI 的征稿范围](https://iui.acm.org/2027/call-for-papers/)。这是贡献匹配建议，不是录用判断或投稿时间承诺。
